## 1.4.0 - 2026-04-13
* The SDK now exposes two new client namespaces — `client.entities` and `client.datasets` — on both the synchronous `CatchAllApi` and asynchronous `AsyncCatchAllApi` clients. The `jobs.initialize()` method accepts a new optional `connected_dataset_ids` parameter that activates Company Search mode. Connection-level errors (`httpx.ConnectError`, `httpx.RemoteProtocolError`) are now automatically retried with exponential backoff in addition to HTTP-status-based retries.
* The `initialize()` method on `JobsClient` (sync and async) now accepts an optional `connected_dataset_ids` parameter. When provided, this activates Company Search mode — the job returns only events relevant to companies in the connected datasets, with each record including a `connected_entities` array scored per company. The dataset must have `latest_status: ready` before the job is submitted.
* The SDK now includes two new top-level modules: `datasets` and `entities`, enabling dataset management and entity operations through the API. Over 30 new types are exported from the top-level package (including `DatasetResponse`, `EntityResponse`, `CreateEntityRequest`, and more). `DefaultAioHttpClient` and `DefaultAsyncHttpxClient` are now available for consumers who need configurable async HTTP transport, installable via the new `aiohttp` optional extra (`pip install newscatcher-catchall-sdk[aiohttp]`).
* The SDK now exports a new `encode_path_param()` utility function from the core module for safe URL path encoding, including proper lowercase boolean serialization. A new `datasets` subpackage has been added, and a `_default_clients` module introduces `DefaultAsyncHttpxClient` and optional `DefaultAioHttpClient` (via the `aiohttp` extra) with sensible defaults.
* The SDK now includes a `datasets` sub-client (`client.datasets`) with full support for the Datasets API. Consumers can create, read, update, and delete datasets; manage entity membership; upload CSV files to create or extend datasets; and retrieve dataset status history. Both synchronous and asynchronous variants are available.
* The SDK now includes `RawDatasetsClient` and `AsyncRawDatasetsClient`, providing a full suite of dataset management methods. New capabilities include creating datasets from entity IDs or CSV files, listing and filtering datasets and their entities, updating dataset metadata, managing entity membership, retrieving status history, and appending entities via CSV upload.
* The SDK now includes an `entities` client for managing company and person entities. New methods available — `list_entities`, `create_entity`, `create_entities_batch`, `get_entity`, `delete_entity`, and `update_entity` — support full CRUD operations with filtering, sorting, pagination, and bulk creation. Both synchronous and asynchronous clients are supported.
* New `RawEntitiesClient` and `AsyncRawEntitiesClient` are now available, providing full CRUD and batch operations for entity management (`list_entities`, `create_entity`, `create_entities_batch`, `get_entity`, `delete_entity`, `update_entity`). These clients return raw `HttpResponse`/`AsyncHttpResponse` wrappers for direct access to HTTP metadata alongside the parsed response data.
* The SDK now includes a full set of types for the Entities and Datasets APIs, enabling entity creation, batch ingestion via CSV, dataset management, and status history tracking. The `Record` type gains a new optional `connected_entities` field that contains relevance-scored entity matches when a search job is submitted with `connected_dataset_ids`.
* The SDK now includes two new response models: `UploadCsvToDatasetResponse` and `ValidationReport`. These models are returned when uploading a CSV to a dataset and provide details on the number of entities created and any rows that were skipped during validation.
