## 1.4.0 - 2026-04-13
* The SDK now exposes two new client namespaces: `entities` (via `client.entities`) and `datasets` (via `client.datasets`), available on both synchronous and asynchronous clients. Job initialization (`jobs.initialize()`) now accepts an optional `connected_dataset_ids` parameter to activate Company Search mode, returning only events relevant to companies in the connected datasets. Connection-level errors (`ConnectError`, `RemoteProtocolError`) are now automatically retried with exponential backoff in addition to retryable HTTP status codes.
* The `initialize()` method on `JobsClient` (sync and async) now accepts an optional `connected_dataset_ids` parameter. When provided, it activates Company Search mode — the job returns only events relevant to companies in the connected datasets, with each record including a `connected_entities` array scored per company.
* The SDK now includes two new top-level modules — `datasets` and `entities` — for managing datasets and entity records. Thirty-plus new types (e.g. `DatasetResponse`, `EntityResponse`, `CreateEntityRequest`, `ValidationReport`) are available from the top-level import. Optional `aiohttp`-based async transport is now supported via the new `aiohttp` extras group (`pip install newscatcher-catchall-sdk[aiohttp]`), and `DefaultAioHttpClient` / `DefaultAsyncHttpxClient` are exported for custom transport configuration.
* The SDK now exports a new `encode_path_param` utility function from the `core` module that correctly encodes values for use in URL path segments, including proper lowercase boolean serialization (`true`/`false`). A new `_default_clients` module is also available, providing `DefaultAsyncHttpxClient` and `DefaultAioHttpClient` with pre-configured 60-second timeouts and redirect following.
* The SDK now includes a `datasets` namespace on both `CatchAllApi` and `AsyncCatchAllApi` clients, providing full access to the Datasets API. New methods support creating, retrieving, updating, and deleting datasets, managing entity membership, uploading CSV files to create or append entities, and querying dataset status history.
* The SDK now includes `RawDatasetsClient` and `AsyncRawDatasetsClient`, providing access to the full Datasets API with raw `HttpResponse` return types. New capabilities include creating and listing datasets, managing dataset entities, uploading CSV files for bulk entity creation, and retrieving dataset status history.
* The SDK now includes an `entities` namespace with full CRUD support for company and person entities. New methods `list_entities`, `create_entity`, `create_entities_batch`, `get_entity`, `delete_entity`, and `update_entity` are available on both the sync `EntitiesClient` and the async `AsyncEntitiesClient`. Access these via `client.entities.*`.
* The SDK now includes `RawEntitiesClient` and `AsyncRawEntitiesClient`, providing full CRUD access to the Entities API. Consumers can list, create (individually or in bulk), retrieve, update, and delete entities, with responses wrapped in `HttpResponse` / `AsyncHttpResponse` for direct access to HTTP metadata.
* The SDK now includes a full suite of entity and dataset management types. New models cover entity creation (`CreateEntityRequest`, `CreateEntityResponse`, `CreateEntitiesBatchResponse`), entity retrieval (`EntityResponse`, `EntityListResponse`, `EntitySummary`), dataset lifecycle (`DatasetResponse`, `DatasetListResponse`, `DatasetStatusHistoryResponse`), and CSV-based bulk ingestion (`CreateDatasetCsvResponse`, `UploadCsvToDatasetResponse`, `ValidationReport`, `SkippedRow`). The `Record` model gains an optional `connected_entities` field populated when a job is submitted with `connected_dataset_ids`.
* The SDK now includes two new response models: `UploadCsvToDatasetResponse` and `ValidationReport`. These models support CSV dataset upload operations and expose fields such as `dataset_id`, `entities_created`, `total_rows`, `valid_rows`, `skipped_count`, and `skipped_rows`.
